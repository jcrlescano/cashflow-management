# API Design — REST `/api/v1`

Part of the Phase 0 design set: [plan](cashflow-app-plan.md) · [architecture](architecture.md) · [database](database-design.md) · **API** · [UI](ui-design.md) · [engineering standards](engineering-standards.md)

---

> **End-to-end encryption note.** Under the privacy design ([privacy-encryption.md](privacy-encryption.md)) the server never receives plaintext amounts, names or notes. Resources below keep their routes and metadata, but every sensitive field travels inside an encrypted `payload` (`{ "id", "metadata": {…plain…}, "payload": "<base64 ciphertext>", "nonce": "…", "keyVersion": 3 }`). Endpoints that **compute** — `/payroll/calculate`, `/tax-tables/{id}/preview`, `/contribution-schemes/{id}/preview`, `/plan-years/{year}/planner`, `/pay-periods/{id}/payday`, `/reports/*`, `/goals/{id}/projection`, `/debts/{id}/payoff`, `/accounts/{id}/interest`, `/plan-years/{year}/tax-summary` — **move into the browser** (same engine, same shapes, called in-process) and are not exposed by the server. The examples in §4 show the decrypted shapes the client works with. Additional server endpoints: `GET/PUT /keys/me` (public key + wrapped private key), `GET /keys/workspace` (wrapped workspace keys for the caller), `POST /keys/workspace/rotate`, `GET /sync/changes?since=<seq>` (change feed).

## 1. Principles

| Topic | Rule |
|---|---|
| Style | Resource-oriented REST over JSON, ASP.NET Core **Minimal APIs** with `MapGroup` per resource and `TypedResults` |
| Base path | `/api/v1` (URL versioning; breaking changes → `/api/v2`, old version kept ≥ 6 months) |
| Contract | OpenAPI 3.1 generated by `Microsoft.AspNetCore.OpenApi`, browsable with Scalar at `/api/docs` (Development environment only); the spec is snapshot-tested so unintended changes fail CI |
| Naming | Plural kebab-case resources (`/tax-tables`), camelCase JSON, enums as strings (`"splitMode": "even"`) |
| Money | JSON **string** decimals (`"1750.00"`) to avoid float loss; currency from workspace settings, or `{ "amount": "1750.00", "currency": "PHP" }` where mixed |
| Dates | `date` = `"2026-11-30"`; timestamps ISO-8601 UTC `"2026-11-21T09:30:00Z"` |
| IDs | UUID v7 strings |
| Errors | **RFC 9457 Problem Details** (`application/problem+json`) with `type`, `title`, `status`, `detail`, `traceId`, and `errors` for validation |
| Validation | FluentValidation per request, run by an endpoint filter → 400 |
| Concurrency | `ETag` (from `xmin`) on GET; `If-Match` required on PUT/PATCH/DELETE → 412 on mismatch |
| Idempotency | `Idempotency-Key` header accepted on POSTs that create money records (transfers done, payments, imports) |
| Pagination | Cursor-based: `?limit=50&cursor=…` → `{ items, nextCursor }`; default 50, max 200 |
| Filtering/sorting | Explicit query params per resource (`?from=2026-01-01&to=2026-06-30&accountId=…&sort=-date`) — no generic query language |
| Partial update | `PATCH` with JSON Merge Patch (`application/merge-patch+json`) for simple fields; dedicated action endpoints for workflows |
| Actions | Workflow steps are sub-resources with `POST`: `/pay-periods/{id}/close`, `/tax-tables/{id}/clone` |
| Auth | BFF session cookie (Google sign-in), antiforgery header `X-XSRF-TOKEN` on unsafe methods; no bearer tokens in the browser |
| Authorization | Policies: `WorkspaceViewer` (GET), `WorkspaceEditor` (writes), `WorkspaceOwner` (members, delete). No admin role. |
| Rate limits | 300 req/min per user; 10/min on `/bff/login` per IP; 429 with `Retry-After` |
| Caching | `Cache-Control: no-store` for financial data; static WASM assets fingerprinted + immutable |

### Status codes

| Code | When |
|---|---|
| 200 / 201 + `Location` / 204 | OK / created / no content |
| 400 | Validation failed (`errors` map) |
| 401 | Not signed in |
| 403 | Signed in, wrong role or workspace |
| 404 | Not found **or** not in your workspace (never reveal existence) |
| 409 | Business conflict (period closed, overlapping rule, bracket gap) — `type` names the rule |
| 412 | `If-Match` mismatch |
| 422 | Import file unreadable |
| 429 | Rate limited |

Problem `type` URIs are stable: `https://cashflow.app/problems/period-closed`, `…/schedule-overlap`, `…/tax-brackets-not-contiguous`, `…/bucket-targets-not-100`, `…/account-cycle`.

## 2. Authentication (BFF, Google)

| Method | Path | Description |
|---|---|---|
| GET | `/bff/login?returnUrl=/` | Starts Google sign-in (OIDC challenge) |
| GET | `/signin-google` | Google callback (handled by the auth middleware) |
| POST | `/bff/logout` | Ends the session |
| GET | `/bff/user` | Current user, roles, active workspace, workspaces list (`401` if signed out) |
| POST | `/bff/workspace` | Switch active workspace `{ workspaceId }` |
| GET | `/bff/invites/{token}` | Invite preview (workspace name, role) — public |
| POST | `/bff/invites/{token}/redeem` | Accept invite after Google sign-in |

Sign-in rule: Google account must be `email_verified`; it is admitted if its `sub` already exists, its email is in the server setting `Auth:AllowedEmails`, or it is redeeming a valid invite. Otherwise → "no access" page.

### 3.8 My account (no admin API)

There is no admin role and no admin endpoint. Who may sign in is the server setting `Auth:AllowedEmails`; the seeded base changes only through releases.

| Method | Path | Purpose |

```http

X-XSRF-TOKEN: …

  "name": "My custom table",
  "countryCode": "PH",
  "method": "bracket",
  "version": {
    "effectiveFrom": "2027-01-01",
    "periodBasis": "annual",
    "brackets": [
      { "lowerBound": "0.00",      "upperBound": "250000.00", "baseTax": "0.00",      "rate": "0.000000" },
      { "lowerBound": "250000.00", "upperBound": "400000.00", "baseTax": "0.00",      "rate": "0.150000" },
      { "lowerBound": "400000.00", "upperBound": null,        "baseTax": "22500.00",  "rate": "0.200000" }

```

                  { "typeId": "…allowance", "period": "p2", "amount": "8000.00" } ] }

  "periods": [

        { "code": "SSS", "employee": "1750.00" }, { "code": "PHILHEALTH", "employee": "2000.00" },

## 5. Client

- `Cashflow.Web` uses **hand-written thin `HttpClient` wrappers** over `Cashflow.Contracts` DTOs (ADR 0013): the server API is small (BFF, keys, encrypted records, change feed, invites), so a generator adds more than it saves.
- A delegating handler adds the antiforgery header, maps Problem Details to a `ProblemException` the UI shows as field errors or a toast, and retries idempotent GETs once on network failure.
